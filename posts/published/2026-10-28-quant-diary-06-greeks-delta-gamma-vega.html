2026년 10월 28일.

#5의 마지막 출력에서 금리와 변동성을 바꿔 가며 콜 가격이 얼마나 움직이는지 봤다. 그 기울기를 정식으로 이름 붙인 게 그릭스(Greeks)다. 한 줄로 적으면, 그릭스는 옵션 가격 함수 V(S, σ, r, t)를 각 입력으로 편미분한 값이고, 리스크관리는 결국 "입력이 조금 움직일 때 가격이 얼마나 움직이는가"를 이 숫자들로 미리 계산해 두는 일이다. 오늘은 델타·감마·베가를 중심으로, 세타와 로까지 공식·QuantLib·범프 앤 리밸류 세 가지 방법으로 같은 값이 나오는지 확인한다.

직관: 가격 함수의 기울기와 휘어짐

옵션 가격을 주가 S 의 함수로 그리면 아래로 볼록한 곡선이 된다. 만기 손익 max(S−K, 0) 은 꺾인 직선인데, 만기 전에는 그 꺾인 점이 매끄럽게 펴진 모양이다.

  • 델타(Δ = ∂V/∂S): 그 곡선의 기울기. 주가가 1 오르면 옵션 가격이 대략 Δ 만큼 오른다. #4 와 #5 에서 본 대로 복제에 필요한 주식 수이기도 하다.
  • 감마(Γ = ∂²V/∂S²): 기울기가 변하는 속도, 즉 곡선의 휘어짐. 주가가 크게 움직일수록 델타만으로는 설명이 안 되는 부분이 감마에서 나온다.
  • 베가(ν = ∂V/∂σ): 변동성이 1%p 오를 때 가격 변화. 그리스 문자가 아닌데도 관습적으로 그릭스에 넣는다.
  • 세타(Θ = ∂V/∂t): 하루 지날 때 가격 변화. 다른 조건이 그대로면 옵션 매수자는 시간이 갈수록 가치를 잃는다.
  • 로(ρ = ∂V/∂r): 금리가 1%p 오를 때 가격 변화.

민감도라는 말이 미분이라는 뜻이다. 그래서 그릭스를 이해하려면 테일러 전개 하나면 충분하다. 가격 변화를 입력 변화의 다항식으로 근사하는 것이다.

수식: 테일러 전개와 블랙숄즈 그릭스

다변수 함수 V(S, σ, r, t) 를 현재 점 근처에서 전개하면 다음과 같다. 주가에 대해서만 2차 항을 남기는 이유는, 옵션에서 가장 크게 휘어 있는 방향이 주가이기 때문이다.

dV ≈ Δ·dS + (1/2)·Γ·(dS)² + ν·dσ + Θ·dt + ρ·dr

블랙숄즈 공식 C = S·N(d1) − K·e^(−rT)·N(d2) 를 직접 미분하면 그릭스가 닫힌 형태로 나온다. 미분 과정에서 S·n(d1) = K·e^(−rT)·n(d2) 라는 항등식이 계속 쓰인다(n 은 표준정규 확률밀도함수). 이 덕분에 d1, d2 를 미분한 항들이 서로 지워져서 결과가 깔끔해진다.

Δ = N(d1)
Γ = n(d1) / (S·σ·√T)
ν = S·n(d1)·√T
Θ = −S·n(d1)·σ / (2√T) − r·K·e^(−rT)·N(d2)     (연 단위, 하루치는 /365)
ρ = K·T·e^(−rT)·N(d2)

감마와 베가 식을 나란히 놓으면 ν = Γ·S²·σ·T 라는 관계가 보인다. 둘 다 n(d1) 에 비례해서, 등가격(ATM) 근처에서 가장 크고 깊은 내가격·외가격으로 갈수록 작아진다. 아래 출력에서 행사가별로 확인한다.

그릭스끼리 묶는 식도 하나 있다. 블랙숄즈 편미분방정식 자체가 그릭스로 쓰여 있다.

Θ + (1/2)·σ²·S²·Γ + r·S·Δ − r·V = 0

델타 헤지를 해서 주가 1차 위험을 없앤 포지션은 무위험이자율만큼 벌어야 한다는 조건을 옮긴 식이다. 이 식을 읽으면 감마를 산 사람은 세타를 낸다는 뜻이 된다. 감마가 크면(주가가 크게 움직일 때 이득) 그 대가로 시간이 갈 때 가치를 잃는다.

예시 숫자: 2026년 10월 27일 코스피로 계산

2026년 10월 27일 코스피는 5,638.35에 마감했다(전 거래일 대비 3.09% 상승). 하루 전에는 1.46% 내렸으니 이틀 사이 주가가 크게 오르내린 셈이고, 감마를 보기에 좋은 날이다. 금리는 10월 22일 동결된 기준금리 연 3.00%를 연속복리로 간주해 쓰고, 로를 확인할 때는 같은 날 국고채 3년물 금리 연 3.758%를 넣는다. 행사가 5,640, 만기 91일, 변동성 연 30%, 배당 없음은 모두 가정이다. 실제 지수옵션의 기초자산은 코스피200이니 숫자 감각을 위한 예시다.

코드에서 그릭스를 구하는 방법은 세 가지를 같이 쓴다. ① 위 공식, ② QuantLib 해석 엔진, ③ 범프 앤 리밸류. 세 번째는 입력을 조금 올리고 내려서 가격을 두 번 다시 계산하고 그 차이로 기울기를 구하는 수치미분(중앙차분)이다.

Δ ≈ [V(S+h) − V(S−h)] / (2h)
Γ ≈ [V(S+h) − 2·V(S) + V(S−h)] / h²

중앙차분의 오차는 h² 에 비례해서, 한쪽으로만 범프하는 전진차분(오차가 h 에 비례)보다 정확하다. 닫힌 공식이 없는 상품에서는 이 방법이 사실상 기본이라, 해석해가 있는 상품에서 두 값이 맞는지 먼저 확인해 두는 게 순서다.

파이썬과 QuantLib으로 확인

import QuantLib as ql
from math import log, sqrt, exp, erf, pi

def N(x): return 0.5*(1+erf(x/sqrt(2)))
def n(x): return exp(-0.5*x*x)/sqrt(2*pi)

# 2026-10-27 코스피 종가 5,638.35 / 기준금리 3.00% (2026-10-22 동결)
S0, K, r, sigma, T = 5638.35, 5640.0, 0.03, 0.30, 91/365   # 행사가·만기·변동성은 가정

# 1) 블랙숄즈 그릭스 공식
d1 = (log(S0/K) + (r + 0.5*sigma**2)*T) / (sigma*sqrt(T))
d2 = d1 - sigma*sqrt(T)
call  = S0*N(d1) - K*exp(-r*T)*N(d2)
delta = N(d1)
gamma = n(d1) / (S0*sigma*sqrt(T))
vega  = S0*n(d1)*sqrt(T)
theta = -S0*n(d1)*sigma/(2*sqrt(T)) - r*K*exp(-r*T)*N(d2)
rho   = K*T*exp(-r*T)*N(d2)
print(f"공식: 콜={call:,.2f} 델타={delta:.4f} 감마={gamma:.6f}")
print(f"      베가(1%p)={vega/100:.2f} 세타(1일)={theta/365:.2f} 로(1%p)={rho/100:.2f}")

# 2) QuantLib 해석 엔진
today = ql.Date(27, 10, 2026); ql.Settings.instance().evaluationDate = today
dc = ql.Actual365Fixed()
spot = ql.SimpleQuote(S0); rq = ql.SimpleQuote(r); volq = ql.SimpleQuote(sigma)
rts = ql.YieldTermStructureHandle(ql.FlatForward(today, ql.QuoteHandle(rq), dc, ql.Continuous))
qts = ql.YieldTermStructureHandle(ql.FlatForward(today, 0.0, dc, ql.Continuous))
vts = ql.BlackVolTermStructureHandle(ql.BlackConstantVol(today, ql.NullCalendar(), ql.QuoteHandle(volq), dc))
proc = ql.BlackScholesMertonProcess(ql.QuoteHandle(spot), qts, rts, vts)
opt = ql.VanillaOption(ql.PlainVanillaPayoff(ql.Option.Call, K), ql.EuropeanExercise(today + 91))
opt.setPricingEngine(ql.AnalyticEuropeanEngine(proc))
print(f"QuantLib: 콜={opt.NPV():,.2f} 델타={opt.delta():.4f} 감마={opt.gamma():.6f} "
      f"베가(1%p)={opt.vega()/100:.2f} 세타(1일)={opt.thetaPerDay():.2f} 로(1%p)={opt.rho()/100:.2f}")

# 3) 범프 앤 리밸류(중앙차분)
def npv(s=S0, v=sigma, rr=r):
    spot.setValue(s); volq.setValue(v); rq.setValue(rr)
    p = opt.NPV(); spot.setValue(S0); volq.setValue(sigma); rq.setValue(r); return p
h = S0*0.01
fd_delta = (npv(s=S0+h) - npv(s=S0-h)) / (2*h)
fd_gamma = (npv(s=S0+h) - 2*npv() + npv(s=S0-h)) / h**2
fd_vega  = (npv(v=sigma+0.01) - npv(v=sigma-0.01)) / 2
print(f"범프(1%): 델타={fd_delta:.4f} 감마={fd_gamma:.6f} 베가(1%p)={fd_vega:.2f}")

# 4) 주가가 움직였을 때: 전체 재평가 vs 델타 근사 vs 델타-감마 근사
P0 = npv()
for m in [-0.03, 0.03, -0.10, 0.10]:
    dS = S0*m
    full = npv(s=S0+dS) - P0
    d_only = delta*dS
    dg = delta*dS + 0.5*gamma*dS**2
    print(f"dS={m:+.0%} ({dS:+,.1f}): 재평가={full:+,.2f} 델타근사={d_only:+,.2f} 델타감마근사={dg:+,.2f}")

# 5) 금리 바꾸기: 기준금리 3.00% -> 국고채 3년 3.758% (2026-10-27)
print(f"r 3.758%: 콜 변화={npv(rr=0.03758)-P0:+.2f}  로 근사={rho*(0.03758-0.03):+.2f}")

# 6) 행사가별 델타·감마·베가 (같은 만기)
for k in [5000, 5360, 5640, 5920, 6300]:
    o = ql.VanillaOption(ql.PlainVanillaPayoff(ql.Option.Call, k), ql.EuropeanExercise(today + 91))
    o.setPricingEngine(ql.AnalyticEuropeanEngine(proc))
    print(f"K={k}: 콜={o.NPV():,.2f} 델타={o.delta():.4f} 감마={o.gamma():.6f} 베가(1%p)={o.vega()/100:.2f}")

# 7) 만기별 ATM 감마·베가·세타
for days in [7, 30, 91, 365]:
    o = ql.VanillaOption(ql.PlainVanillaPayoff(ql.Option.Call, K), ql.EuropeanExercise(today + days))
    o.setPricingEngine(ql.AnalyticEuropeanEngine(proc))
    print(f"{days}일: 감마={o.gamma():.6f} 베가(1%p)={o.vega()/100:.2f} 세타(1일)={o.thetaPerDay():.2f}")

출력에서 읽은 것

  • 세 방법이 같은 값을 준다. 공식과 QuantLib 은 소수 넷째 자리까지 같고, 주가 1% 범프의 중앙차분도 델타 0.5488, 감마 0.000469, 베가 11.15 로 거의 일치한다. 범프 크기를 너무 크게 잡으면 곡률 때문에, 너무 작게 잡으면 부동소수점 오차 때문에 값이 흔들린다. 1% 는 이 예시에서 둘 사이 균형이 맞는 크기였다.
  • 3% 움직임에서는 델타만으로 부족하다. 어제 코스피처럼 3% 오르면 실제 가격 변화는 +99.41 인데 델타 근사는 +92.85 다. 감마 항 (1/2)·Γ·(dS)² ≈ 6.70 을 더하면 +99.55 로 거의 맞는다. 내릴 때도 마찬가지로 −86.04 대 −86.14. 볼록성 덕분에 콜 매수자는 오를 때 더 벌고 내릴 때 덜 잃는다.
  • 10% 움직임에서는 감마 근사도 어긋나기 시작한다. +10% 에서 재평가 +377.52, 델타-감마 근사 +384.00 으로 6 이상 차이가 난다. 3차 이상 항(감마 자체가 주가에 따라 변하는 효과)이 커지기 때문이다. 큰 충격 시나리오에서는 근사 대신 전체 재평가를 하는 이유가 여기 있다.
  • 로 근사는 잘 맞는다. 금리를 3.00% 에서 국고채 3년물 3.758% 로 바꾸면 실제 변화 +5.20, 로로 계산한 근사 +5.18. 가격이 금리에 대해서는 거의 직선이라 1차 근사로 충분하다.
  • 감마와 베가는 등가격에서 가장 크다. 행사가 5,640 근처에서 감마 0.000469, 베가 11.15 로 가장 크고, 깊은 내가격(5,000)이나 외가격(6,300)으로 갈수록 작아진다. 델타는 행사가가 낮을수록 1 에, 높을수록 0 에 가까워진다.
  • 만기가 짧을수록 감마·세타가 커지고 베가는 작아진다. 등가격 기준 7일 만기 감마는 0.001702 로 91일의 약 3.6배, 하루 세타는 −6.90 으로 약 3.3배다. 반대로 베가는 1년 만기 21.81 이 7일 만기 3.11 의 7배 넘는다. 감마는 1/√T, 베가는 √T 에 비례하는 식 그대로다.
  • 세타와 감마는 같이 움직인다. 위 편미분방정식에 이 예시 값을 넣으면 하루 세타 −2.06 가운데 약 −1.84 가 감마 항(½σ²S²Γ)에 대응하고, 나머지는 금리 항이다. 감마를 산 대가가 시간가치 감소로 나간다는 뜻이다.

리스크관리에서 그릭스를 쓰는 법

석사 때 배운 리스크관리 흐름은 이렇다. 포트폴리오의 그릭스는 개별 상품 그릭스의 합이다(미분이 선형이라서). 그래서 상품마다 그릭스를 구해 더하면 포트폴리오가 어느 방향 위험에 얼마나 노출됐는지 한 줄로 나온다.

  • 델타 헤지: 콜 1계약을 팔았다면 기초자산을 Δ 만큼 사서 1차 위험을 없앤다. 다만 주가가 움직이면 델타가 감마만큼 변하므로 계속 다시 맞춰야 한다. 감마가 클수록 재조정이 잦아지고 비용이 커진다.
  • 감마·베가 헤지: 주식으로는 감마와 베가를 없앨 수 없다(주식의 감마·베가는 0). 다른 옵션을 섞어야 한다. 그래서 헤지할 그릭스 수만큼 서로 다른 헤지 수단이 필요하고, 이는 연립방정식(선형대수) 문제가 된다.
  • 시나리오와 근사: 작은 움직임은 델타-감마 근사로 빠르게 손익을 추정하고, 큰 충격은 전체 재평가로 확인한다. 위 출력의 3% 와 10% 비교가 그 기준을 정하는 감각이다.

금리 상품에서도 같은 생각이 그대로 쓰인다. #3의 듀레이션은 채권 가격의 금리 델타, 컨벡시티는 금리 감마에 해당한다. 이름만 다르고 테일러 전개 1차·2차 항이라는 점은 같다.

자주 묻는 질문

Q. 델타를 행사 확률로 읽어도 되나?

안 된다. 콜 델타는 N(d1) 이고, 위험중립 행사 확률은 N(d2) 다. 이 예시에서도 델타 0.5489 와 N(d2) 는 다르다. 둘의 차이는 σ√T 만큼 d1 과 d2 가 벌어진 데서 나오고, 변동성이 크거나 만기가 길수록 차이가 커진다. #5 에서 본 대로 N(d2) 도 실제 세계의 확률은 아니다.

Q. 베가는 블랙숄즈에서 σ 가 상수라면서 왜 미분하나?

모형 안에서는 상수지만 시장에서 쓰는 내재변동성은 매일 바뀐다. 그래서 "모형에 넣는 σ 를 바꾸면 가격이 얼마나 바뀌나"를 재는 실무용 민감도로 쓴다. 모형 자체가 일관적이지 않다는 지적이 있고, 그래서 확률변동성 모형이 나왔다. 로드맵 뒤쪽 이야기다.

Q. 범프 크기는 어떻게 정하나?

정답은 없다. 너무 크면 곡률이 섞이고(절단 오차), 너무 작으면 가격 계산의 수치 오차가 커진다(반올림 오차). 해석해가 있는 상품에서 범프 결과를 공식과 비교해 크기를 정하고, 몬테카를로처럼 가격 자체에 잡음이 있는 엔진에서는 같은 난수를 써서 범프 전후를 계산해야 차분이 안정된다. 다음 일기에서 다룬다.
